JARVIS × Claude Code

How it works now, what you can do, and where it's going

Your goal
A JARVIS that actually feels like you're talking to it — snappy, natural conversation — that is hard-wired to Claude Code so it can do everything claude --dangerously-skip-permissions can do: run commands, read/write files, browse, build software, control your machine — all by voice.

01The big idea — one persistent brain

Before: every time you spoke, JARVIS launched a brand-new claude -p process. That "cold start" (boot + load context) happened every single turn — the main reason it felt sluggish. It also forgot what it just did between turns.

Now (Phase 1, done ✅): JARVIS holds one long-lived Claude Code session open and talks to it across turns. No cold start, real memory, and the full Claude Code toolbox is live the whole time.

Warm turns dropped from a full cold-start to ~2.3 seconds — and it now remembers the conversation.

04Running many tasks at once (not waiting)

One session is a single conversation — it does one thing at a time, in order (like one Claude Code chat). To run things in parallel, you don't cram them into that one session; you fan out:

PatternHowBest for
Background tasksJARVIS spawns a separate Claude Code session for a long job and keeps chatting with you on the main one. It narrates progress when done."Build X" while you keep talking
Session poolKeep N warm sessions; route each new request to a free one → true concurrency.Several quick jobs at once
Fire-and-reportKick off a task, get an instant "On it, sir," then a voice ping when it finishes.Anything slow you don't want to wait on

JARVIS already has a task manager + work-session system — Phase 3 wires these into the persistent brain so you can say "do A, and also start B" and it runs B in the background while A continues.
